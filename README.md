# VITalWatch — AIIA Clinical Trial Management + Pharmacovigilance

A clinical trial management and monitoring dashboard for the **All India Institute of Ayurveda**,
with an integrated pharmacovigilance module for the **National Pharmacovigilance Coordination
Centre (NPvCC)** for ASU&H drugs.

> **Demonstration system. Every record is synthetic and generated by `app/datagen.py`.
> No real participant, trial or institutional data is present at any stage.**
>
> Adverse-event terms are coded against a curated vocabulary written for this project.
> **MedDRA and WHODrug are licensed commercial dictionaries and are not used in this build.**

Build plan and phase checklists: [ROADMAP.md](./ROADMAP.md).
Demo path, compliance mapping and Q&A prep: [`docs/`](./docs).

## Run it

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
./scripts/run.sh                     # http://localhost:8000
```

The database seeds itself on first start. To rebuild it from scratch at any point:

```bash
./scripts/seed.sh                    # ~2 seconds, identical data every time
```

The seed is fixed (`SEED_RANDOM_SEED=20260822`), so the app, the deck and the demo video can
never disagree about a number.

## Screens

| Path | What it shows |
|---|---|
| `/portfolio` | Six portfolio KPIs across all studies, severity-ranked alerts, study table |
| `/study/{id}` | Enrolment against plan-to-date, sites, milestone timeline, deviations, open queries |
| `/ae` | Adverse-event register and intake form — coding and statutory clocks on submit |
| `/signals` | Coded terms ranked by proportional reporting ratio, for DSMB triage |
| `/audit` | The hash-chained audit trail, filterable, with a **Verify chain** button |
| `/docs` | OpenAPI — KPIs, alerts, coding, signals, chain verification, FHIR, SDTM export |

## From the command line

```bash
python -m app.pv "loose motion since yesterday"    # → Diarrhoea  VW-T0012  0.91  phrase
python -m app.audit --verify                       # walks the chain; names the first broken row
python -m app.alerts                               # evaluates every rule at current thresholds
ENROLMENT_LAG_PCT=95 python -m app.alerts          # 8 alerts → 10. Thresholds are configuration
python -m app.signals                              # ranked study/term disproportionality
python -m app.sdtm STU-002 > dm.csv                # CDISC SDTM Demographics domain
python -m app.fhir STU-003                         # study as a FHIR R4 ResearchStudy
./scripts/deploy_check.sh [base-url]               # 13 endpoints, local or deployed
```

## Stack

FastAPI · Jinja2 server-rendered templates · SQLite via stdlib `sqlite3` · Tailwind and Chart.js
from a CDN. **One process, one file, no build step.** See [`docs/architecture.md`](./docs/architecture.md)
for why, and for the three points where this swaps to a production posture.

## The audit trail

Each row stores `sha256(canonical_json(payload) + prev_hash)` plus a gapless sequence number, so
both alteration and deletion are detectable. Verification names the first offending row rather
than reporting a generic failure.

`UPDATE` and `DELETE` on `audit_events` are refused by **database triggers**, so the guarantee
does not depend on the application being uncompromised:

```bash
sqlite3 data/ctms.db "UPDATE audit_events SET after_json='{}' WHERE seq=3;"
# Error: audit_events is append-only: UPDATE is not permitted
```

## Not built, deliberately

Authentication and role-based access control; licensed dictionaries; live EDC / HIS / ABDM
exchange (the FHIR resource shapes exist, a counterparty does not); SDTM beyond the `DM`
domain; PostgreSQL. Each is a scoping decision with a stated reason in
[`docs/compliance-matrix.md`](./docs/compliance-matrix.md) — nothing in this repository claims a
capability it does not have.
